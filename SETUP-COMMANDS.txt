====================================================================
 TASKTRACKER COMMANDS — current project
====================================================================

This file matches the current TaskTracker repository, which contains a
FastAPI churn-prediction service, model-training scripts, Docker Compose,
Kubernetes manifests, and GitHub Actions CI/CD workflows.

The model/API still uses churn-prediction feature and response names because
that is the implemented business functionality. TaskTracker is the project,
application, container, and deployment name.

--------------------------------------------------------------------
1. Required tools
--------------------------------------------------------------------

- Git
- Python 3.11+
- Docker Desktop with Docker Compose
- kubectl and a Kubernetes cluster for Kubernetes deployment
- GitHub CLI (gh), optional for repository and Actions administration

    git --version
    python --version
    docker --version
    docker compose version
    kubectl version --client
    gh --version

--------------------------------------------------------------------
2. Install Python dependencies
--------------------------------------------------------------------

    python -m venv .venv

Windows PowerShell:

    .\.venv\Scripts\Activate.ps1

macOS/Linux:

    source .venv/bin/activate

    python -m pip install --upgrade pip
    pip install -r requirements.txt -r requirements-dev.txt

--------------------------------------------------------------------
3. Train and validate the model locally
--------------------------------------------------------------------

    python train_model.py
    python check_quality_gate.py
    pytest -v
    ruff check .
    pip-audit -r requirements.txt --strict

Training creates model.pkl and refreshes metrics.json. These generated files
are required by the API and Docker image but are not source-code files.

--------------------------------------------------------------------
4. Run the FastAPI service locally
--------------------------------------------------------------------

    python train_model.py
    uvicorn app:app --reload

In another terminal:

    curl http://localhost:8000/health
    curl http://localhost:8000/version
    curl -X POST http://localhost:8000/predict/ -H "Content-Type: application/json" -d '{"tenure_months":12,"monthly_charges":70,"total_charges":840,"contract_type":0,"support_calls":2,"is_senior_citizen":0,"has_tech_support":0}'

Open http://localhost:8000/ for the TaskTracker web form.

--------------------------------------------------------------------
5. Run the full TaskTracker stack with Docker Compose
--------------------------------------------------------------------

    python train_model.py
    python check_quality_gate.py
    docker compose up --build -d
    docker compose ps
    docker compose logs -f app

Verify the application:

    curl http://localhost:8000/health
    curl http://localhost:8000/version

Stop the stack and retain the PostgreSQL volume:

    docker compose down

Stop the stack and delete the PostgreSQL volume:

    docker compose down -v

--------------------------------------------------------------------
6. Build and run the TaskTracker Docker image directly
--------------------------------------------------------------------

    python train_model.py
    python check_quality_gate.py
    docker build -t tasktracker:latest .
    docker run --rm -p 8000:8000 tasktracker:latest

The Dockerfile expects model.pkl, metrics.json, and VERSION in the build
context. CI creates the model artifact before the CD workflow builds the image.

--------------------------------------------------------------------
7. Deploy TaskTracker to Kubernetes
--------------------------------------------------------------------

Check the selected cluster:

    kubectl config current-context
    kubectl cluster-info
    kubectl get nodes

For Docker Desktop Kubernetes, build the local image first:

    python train_model.py
    python check_quality_gate.py
    docker build -t tasktracker:latest .

Apply database resources, then application resources:

    kubectl apply -f k8s/db-secret.yaml
    kubectl apply -f k8s/db-configmap.yaml
    kubectl apply -f k8s/db-service.yaml
    kubectl apply -f k8s/db-statefulset.yaml
    kubectl apply -f k8s/app-secret.yaml
    kubectl apply -f k8s/app-configmap.yaml
    kubectl apply -f k8s/app-service.yaml
    kubectl apply -f k8s/app-deployment.yaml

Verify the deployment:

    kubectl get pods -w
    kubectl get statefulset postgres-db
    kubectl get deployment tasktracker-app
    kubectl get pvc
    kubectl rollout status statefulset/postgres-db
    kubectl rollout status deployment/tasktracker-app
    kubectl get services
    kubectl get endpoints db-service tasktracker-app-service
    kubectl logs deployment/tasktracker-app

Local API verification through the Kubernetes Service:

    kubectl port-forward service/tasktracker-app-service 8000:80
    curl http://localhost:8000/health

Optional Ingress deployment (requires an NGINX Ingress Controller and DNS or
hosts-file resolution for tasktracker.internal.example.com):

    kubectl apply -f k8s/ingress.yaml
    kubectl get ingress tasktracker-ingress

--------------------------------------------------------------------
8. GitHub Actions CI/CD
--------------------------------------------------------------------

CI runs on pushes to main and pull requests. It performs:

- Ruff linting
- pip-audit dependency scanning
- Model training and the F1/ROC-AUC quality gate
- pytest tests using the trained model artifact

The CD workflow runs after a successful CI run on main. It builds the
tasktracker image, scans it with Trivy, pushes versioned/candidate tags to
Docker Hub, and requires manual approval before promoting latest.

Optional GitHub CLI setup:

    gh auth login
    gh repo create tasktracker --public --source=. --remote=origin --push
    gh secret set DOCKERHUB_USERNAME --body "<your-dockerhub-username>"
    gh secret set DOCKERHUB_TOKEN --body "<your-dockerhub-access-token>"
    gh secret list
    git add .
    git commit -m "chore: initial TaskTracker submission"
    git push origin main

Watch workflows:

    gh run list --workflow=ci.yml
    gh run watch
    gh run list --workflow=cd.yml

Create a GitHub Environment named production and configure required reviewers
before using the production-promotion job.

--------------------------------------------------------------------
9. Push and run a registry image
--------------------------------------------------------------------

Replace the registry and username placeholders with real values:

    docker tag tasktracker:latest <username>/tasktracker:latest
    docker push <username>/tasktracker:latest
    docker pull <username>/tasktracker:latest
    docker run --rm -p 8000:8000 <username>/tasktracker:latest
    curl http://localhost:8000/health

Never commit real passwords, tokens, or production secret values.
